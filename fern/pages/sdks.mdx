---
title: "SDKs for the Orders API"
subtitle: Typed TypeScript and Python clients, generated from the same OpenAPI spec — no hand-written HTTP.
---

The Orders API ships with **idiomatic SDKs** generated by [Fern](https://buildwithfern.com) straight
from `orders.yaml`. Same source of truth as the docs and the Postman collection — so the SDKs stay in
lockstep with the API: change the spec, regenerate, done.

<Note>
These SDKs are generated artifacts committed to the repo. Browse the full source in the cards below,
or regenerate locally with `fern generate --api orders --group ts-sdk --local` (and `python-sdk`).
</Note>

## Create an order

<CodeBlocks>
```typescript title="TypeScript"
import { PostmanApiCatalogDemoApiClient } from "./src/Client";

const client = new PostmanApiCatalogDemoApiClient();

await client.orders.createOrder({
  customerId: "usr-002",
  total: 99.5,
  status: "pending",
  currency: "USD",
});
```

```python title="Python"
from postman_api_catalog_demo import PostmanApiCatalogDemoApi

client = PostmanApiCatalogDemoApi()

client.orders.create_order(
    customer_id="usr-002",
    total=99.5,
    status="pending",
    currency="USD",
)
```
</CodeBlocks>

Both clients give you typed request/response models, built-in error types, retries, and configurable
timeouts out of the box.

## How it fits together

One OpenAPI spec (`orders.yaml`) drives **four** outputs: the interactive API reference, the Postman
collection, the MCP server for AI agents, and these SDKs. That's the payoff of a spec-first workflow —
every surface updates from a single change.
