title: Async notifications (MQTT)
subtitle: Real-time, event-driven notifications over MQTT
---

Beyond the REST APIs, the Retail Commerce platform delivers **real-time notifications** over
MQTT — documented here as a guide because it's an asynchronous channel, not a REST endpoint.

## Flow

```
Your app  ──publish──▶  broker.hivemq.com:1883
                         topic: postman-api-catalog-demo/notifications
                                    │
                          Retail Commerce notifications service
                                    │
                                    ▼
                     POST notification.processed ──▶ your webhook
```

## Publish a message

Publish a JSON message to:

- **Broker:** `mqtt://broker.hivemq.com:1883`
- **Topic:** `postman-api-catalog-demo/notifications`

Our notifications service consumes the message and forwards a `notification.processed`
event to your configured webhook.

<Note>
MQTT is a messaging protocol, so it isn't part of the REST API Reference — it's handled by our
managed notifications service.
</Note>
