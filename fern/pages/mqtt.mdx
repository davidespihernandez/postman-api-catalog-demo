title: Async notifications (MQTT)
subtitle: Event-driven notifications over MQTT
---

Beyond the REST APIs, the demo includes an **event-driven notifications** flow over MQTT —
documented here as a guide because it's an async (AsyncAPI) channel, not a REST endpoint.

## Flow

```
Postman  ──publish──▶  broker.hivemq.com:1883
                        topic: postman-api-catalog-demo/notifications
                                   │
                         mqtt-bridge (always-on, on the AWS VM)
                                   │
                                   ▼
                    POST notification.processed ──▶ your webhook
```

## Publish a message

Publish a JSON message from the **Notifications (MQTT)** collection in Postman to:

- **Broker:** `mqtt://broker.hivemq.com:1883`
- **Topic:** `postman-api-catalog-demo/notifications`

An always-on bridge on the server consumes it and forwards a `notification.processed`
event to the configured notification webhook — nothing runs on your laptop.

<Note>
MQTT is a messaging protocol, so it isn't part of the REST API Reference. The bridge is a
systemd service on the same VM that hosts the three APIs.
</Note>
